# FAVELLA 1 — Note tecniche di rilascio v0.12.0

**Livello 6 della roadmap del linguaggio — «Maturità linguaggio/toolchain» COMPLETATO.**
Release minore che consolida le patch `0.11.1` → `0.11.3`. Tre obiettivi, tutti
realizzati senza toccare l'invariante della grammatica (LALR(1) 0-ambigua per
costruzione). La superficie pubblica `analizza_file()` resta invariata.

Suite del linguaggio: **321 asserzioni** (era 287 a inizio livello), tutte verdi,
inclusa la guardia anti-ambiguità (1 albero / 0 conflitti LALR).

---

## 1. Linter semantico (0.11.1)

Analisi statica **non bloccante** sul `Mondo` compilato, in coda a
`FavellaTransformer.valida_post()` (metodo `analisi_statica`), che emette avvisi
sul canale `warnings` già esistente. **Nessuna modifica alla grammatica.**

Quattro controlli:

- **Stanze irraggiungibili** — reachability (BFS) dal punto di partenza
  (`Il giocatore comincia in …`, o la prima stanza) lungo le uscite `collega`.
- **Oggetti orfani** — oggetti (NPC, contenitori e supporti inclusi) con
  `posizione` nulla e mai introdotti da una conseguenza di spostamento.
- **Regole morte** — regole oscurate da una precedente con identica firma
  *(verbo, bersaglio, secondario, preposizione)* che scatta sempre. Criterio
  **conservativo** allineato all'ordine delle fasi del runtime
  (`gioco._esegui_comando`): per le regole specifiche scatta solo se la corrente
  è incondizionata; per le globali sempre. Zero falsi positivi.
- **Stati/contatori inutilizzati** — variabili dichiarate ma mai lette in una
  condizione, conseguenza o interpolazione `[var]`.

## 2. Moduli / import multi-.fav (0.11.2)

Preprocessore **Passata 0** (`compilatore.espandi_inclusioni`): la direttiva
`Includi "file.fav".` è espansa testualmente in un unico sorgente **prima** delle
due passate, quindi non raggiunge mai il parser (invariante LALR intatto).
Caratteristiche: path relativi, deduplica dei diamanti, rilevamento dei cicli
(errore bloccante), file mancante (errore bloccante) e **source map**
riga-espansa → (file, riga) per attribuire gli errori al file e alla riga
originali. Il path è vocabolario nuovo tra virgolette; le direttive dentro
stringhe/commenti non vengono interpretate.

## 3. Specifica EBNF formale versionata (0.11.3)

Nuovo documento tecnico **`documentazione/grammatica-0.12.0.md`**: scheletro
statico della grammatica in EBNF (sintassi Lark), modello dei **terminali chiusi
generati per-file** (`ENTITA`/`VARIABILE`/`DIREZIONE`), priorità lessicali
(`PROPRIETA`, `NUMERO`, `_PREP_DESCR`) e invariante LALR(1). È la spec dal lato
compilatore, **non** il manuale d'autore. Guardia anti-drift nella suite: la spec
deve citare tutte le regole `def_/cond_/cons_` di `_GRAMMAR_TEMPLATE`.

> `i18n` è stato **scartato** da questo ciclo.
